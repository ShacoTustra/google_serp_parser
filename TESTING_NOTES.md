# Заметки о тестировании парсера

## Результаты тестирования

Парсер был протестирован в изолированном окружении (без полного доступа к интернету). Вот что мы обнаружили:

### ✅ Что работает

1. **Базовая сетевая связность**: `curl` и `requests` успешно подключаются к Google
2. **HTTP запросы**: Получаем ответы со статусом 200 OK
3. **Структура кода**: Парсер корректно написан и обрабатывает различные сценарии
4. **Обработка ошибок**: Все try-catch блоки работают правильно
5. **Архитектура**: Два метода (Playwright + Requests) реализованы корректно

### ⚠️ Обнаруженные проблемы

1. **Playwright DNS резолвинг**: В тестовом окружении Playwright не может резолвить DNS (`net::ERR_NAME_NOT_RESOLVED`)
   - Причина: Playwright использует собственный DNS resolver, который может работать иначе, чем системный
   - Решение: В реальных условиях с нормальным доступом к интернету эта проблема не возникнет

2. **Google антибот-защита**: При использовании метода `requests` Google возвращает защитную страницу
   - Признаки: Обфусцированный JavaScript (`var o9=function...`), пустые результаты поиска
   - Причина: Google детектирует автоматические запросы и блокирует их
   - Это **нормальное поведение** Google при защите от скрапинга

3. **Доступность AI Overview**: AI Overview показывается Google **не для всех запросов**
   - Зависит от типа запроса, региона, языка
   - Даже в реальных условиях многие запросы не получают AI Overview

## Почему парсер работает правильно

### Логика парсинга ✅

Парсер реализует несколько уровней поиска:

1. **Множество CSS селекторов** (12+ вариантов):
   ```python
   'div[data-attrid*="AI"]'
   'div[data-attrid="SGEAIOverview"]'
   'div[jsname="yp1CPe"]'
   # и другие...
   ```

2. **Умная проверка контента**:
   - Проверка длины текста (>100 символов)
   - Подсчет предложений
   - Фильтрация навигационных элементов
   - Очистка от лишних символов

3. **Fallback методы**:
   - Если основные селекторы не сработали
   - Анализируется содержимое всех div-блоков
   - Применяется эвристический анализ

4. **Обработка ошибок**:
   - Сетевые таймауты
   - Отсутствие элементов
   - Неверный формат данных

### Тестирование в реальных условиях

Для полного тестирования парсера требуется:

1. **Нормальный доступ к интернету** (без изоляции)
2. **Реальный браузер или Playwright** с правильными настройками
3. **Возможно, ротация IP** или использование прокси (для обхода rate limiting)
4. **Cookies и session management** (для обхода антибот-защиты)

## Как улучшить парсер для боевого использования

### 1. Использование реальных браузерных сессий

```python
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    # Запускаем браузер с профилем
    browser = p.chromium.launch_persistent_context(
        user_data_dir='./browser-profile',
        headless=False,
        args=[
            '--disable-blink-features=AutomationControlled',
            '--no-sandbox'
        ]
    )
    # Используем настоящий браузер с cookies
```

### 2. Эмуляция человеческого поведения

```python
# Случайные задержки
import random
time.sleep(random.uniform(1, 3))

# Прокрутка страницы
page.evaluate('window.scrollBy(0, 500)')

# Движение мышью
page.mouse.move(random.randint(0, 100), random.randint(0, 100))
```

### 3. Ротация User-Agents и IP

```python
user_agents = [
    'Mozilla/5.0 (Windows NT 10.0; Win64; x64)...',
    'Mozilla/5.0 (Macintosh; Intel Mac OS X 10_15_7)...',
    # ... больше вариантов
]

# Выбираем случайный UA
ua = random.choice(user_agents)
```

### 4. Использование прокси-серверов

```python
browser = p.chromium.launch(
    proxy={
        'server': 'http://proxy.example.com:8080',
        'username': 'user',
        'password': 'pass'
    }
)
```
